# Campusly — College Event Website & Student Performance Predictor

A responsive student event dashboard concept for college clubs. The project demonstrates event discovery, event management endpoints, event registration, a student performance estimate, database persistence, API documentation, and a clear path to cloud deployment.

> **Project status:** This submission starter contains a polished, interactive standalone dashboard (`frontend/preview.html`) and a working FastAPI + SQLite backend (`backend/main.py`). The standalone dashboard uses in-browser sample data for its demo; it is not yet wired to the API. The backend is functional independently and exposes interactive Swagger docs at `/docs`. Connect the dashboard to the API as the next integration step before describing the entire application as end-to-end integrated.

## Features

- Responsive dashboard layout with event cards, student stats, activity, and involvement chart.
- Search events, switch dashboard views, register/cancel registrations in the standalone demo, and add an event in the current page session.
- Performance estimate based on attendance, previous marks, study hours, and assignment completion.
- REST API for event listing, filtering, creation, updates, deletion, registrations, student registrations, stats, and prediction.
- SQLite database with seed events; data persists across API restarts.
- OpenAPI/Swagger docs generated by FastAPI.

## Technology stack

- Frontend demo: HTML5, CSS3, vanilla JavaScript
- Backend: Python 3.10+, FastAPI, Uvicorn, Pydantic
- Database: SQLite (simple local setup; PostgreSQL is recommended for production)
- Prediction: transparent weighted baseline in Python; not a trained or validated ML model
- Version control: Git and GitHub
- Deployment options: Vercel for static frontend; Render or another Python-compatible host for API; managed PostgreSQL for production

## Run locally

### 1. Start the backend API

```bash
cd backend
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload
```

API runs at `http://127.0.0.1:8000`.

- Health check: `http://127.0.0.1:8000/health`
- Swagger API docs: `http://127.0.0.1:8000/docs`
- Event list: `http://127.0.0.1:8000/api/events`

The SQLite database is created automatically in the backend directory and seeded on first run.

### 2. Open the frontend demo

Open `frontend/preview.html` directly in a modern browser. It is a self-contained UI demo and does not require npm or a build step. Its sample registrations and newly added events are in-memory and reset on reload.

## API reference

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/health` | Health check |
| GET | `/api/events` | List events; optional `q`, `category`, `student_id` query params |
| GET | `/api/events/{event_id}` | Event details |
| POST | `/api/events` | Create an event |
| PUT | `/api/events/{event_id}` | Update an event |
| DELETE | `/api/events/{event_id}` | Delete an event |
| POST | `/api/events/{event_id}/registrations` | Register a student (`student_id`) |
| DELETE | `/api/events/{event_id}/registrations/{student_id}` | Cancel registration |
| GET | `/api/students/{student_id}/registrations` | List a student's registrations |
| POST | `/api/predict` | Calculate illustrative performance estimate |
| GET | `/api/stats` | Event and registration summary |

Example prediction request:

```bash
curl -X POST http://127.0.0.1:8000/api/predict \
  -H "Content-Type: application/json" \
  -d '{"attendance":88,"previous_marks":78,"study_hours":2.5,"assignments_completed":85}'
```

Example event request:

```bash
curl -X POST http://127.0.0.1:8000/api/events \
  -H "Content-Type: application/json" \
  -d '{"title":"Cloud Computing Meetup","category":"Technical","event_date":"2026-11-12","event_time":"2:00 PM","venue":"Seminar Hall","capacity":60,"description":"Student cloud community meetup"}'
```

## Suggested production improvements

- Wire the frontend event list and registration buttons to the API using `fetch` and environment-based API URLs.
- Add authentication and role-based authorization before enabling admin routes publicly.
- Replace SQLite with PostgreSQL for hosted multi-user deployments.
- Add database migrations, automated tests, rate limiting, secure secrets, structured logs, and CI.
- Train and evaluate an ML model only if an appropriate, lawful dataset is available. Keep predictions explainable and low-stakes.
- Add privacy notices and collect only the student information required.

## Short project explanation

Campusly is a college event management website designed to centralize event discovery and student participation. The frontend presents upcoming events and engagement information, while a FastAPI REST backend manages event data and registrations in SQLite. A student performance feature returns an illustrative estimate based on attendance, prior marks, study hours, and assignment completion. The project demonstrates API development, data persistence, responsive UI design, documentation, version control, and a cloud deployment pathway.
